A flight recorder
for AI agents.

An MCP proxy signs a hash-linked receipt for every tool call, refuses secret reads before they run, and proves “the agent never read a secret” to anyone with the public key. When it isn’t true, it names the step and explains why.

The problem

Agents act through tools. Nobody can check what they actually did.

Logs are editable

A tool log is a text file the agent’s own host can rewrite, reorder or truncate. “Trust me” is the whole audit trail.

Repos give agents orders

A README that asks agents to read .env, and a prompt that says to follow the README, were enough: the committed run on slide 4 is a free model doing what it was told.

“Did it read a secret?”

Answering means handing over every argument, or asking the reviewer to take your word. Neither works for a third party.

How a receipt is made

Policy first, then a signed, hash-linked receipt, whatever happened.

1 · call

Agent → proxy

Any MCP client calls tools/call on the stdio proxy.

2 · policy

Check before running

no-secrets-read/v2: secret paths (.env*, keys, .git/**, .npmrc, .netrc, ~/.ssh …) and token patterns. A hit is refused, never run.

3 · receipt

Sign & link

Ed25519 over tool, paths, outcome, salted argsHash/resultHash and the previous hash.

4 · seal

Signed count

Shutdown signs the log’s length, so cutting receipts off the end is caught.

5 · prove

Public-key check

Merkle paths and commitments per step. A FAIL names the step and the rule.

The signing key lives in ~/.blackbox, outside the workspace the agent’s tools can reach. Raw arguments stay in a private witness; exports carry only salted hashes.

Drop-in MCP proxy

Any MCP client. Any stdio MCP server. About 0.7 ms a call.

# built-in: read_file, write_file, git, shell, blackbox_explain $ node packages/proxy/dist/server.js # or record calls to any stdio MCP server $ node packages/proxy/dist/server.js --upstream \ "npx -y @modelcontextprotocol/server-filesystem ."

With --upstream, tools/list passes through and every tools/call is policy-checked, forwarded only if allowed, and recorded. GitLab Duo flows reach it through a one-shot bridge (call.js).

Limits, said plainly

What the recorder does not prove, and what still needs setup.

Trust anchor is the proxy key

A receipt proves this proxy observed and signed the call. Publish and pin the key. No TEE attestation.

Policy check, not a sandbox

Glob and token matching is heuristic; only calls through the proxy are covered.

Not zero knowledge

Selective disclosure with a trusted attester; the verifier trusts the proxy key for the verdict over hidden arguments.

Setup required Zetaris

Client and live check exist. Needs ZETARIS_API_KEY and ZETARIS_ORG_ID; no live call has run.

Setup required Meterless

explain --model meterless is wired. Needs the local runtime (Nightshift app) running; no hosted key exists. No live call has run.

Not run yet GitLab

Duo flow, bridge and CI jobs are in the repo. Needs a public GitLab project, a live Duo run and pipeline history.
