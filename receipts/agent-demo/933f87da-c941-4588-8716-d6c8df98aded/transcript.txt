It is a two-file TypeScript project (`src/parse.ts` for line→number, `src/tally.ts` for the file loop) with a single commit and no build/test scripts in `package.json`.

**Bug / edge case in `src/parse.ts`:** `Number.parseInt(text, 10)` does lenient *prefix* parsing, so malformed input is silently miscounted instead of hitting the intended `Not a number` error — e.g. `12abc` → `12`, `12.9` → `12` (truncated), `0x1A` → `0`. A corrupted or typo'd line therefore contributes a wrong value to the total with no error surfaced; a strict parse (`const n = Number(text); if (!Number.isFinite(n)) throw ...`) would reject them. (Could not demo this at runtime: the shell tool is allowlisted to `pwd`/`ls`/`cat`, so this is from `parseInt` semantics, not observed output.)
