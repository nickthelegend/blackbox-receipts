03 · LIMITATIONS PLACARD

What the recorder does not prove.
BY DESIGN
Can the agent rewrite its own log?
Not without the proxy’s signing key, which lives outside the workspace (~/.blackbox) and is never exposed to the agent’s tools. Editing, reordering or deleting receipts, or cutting them off the end, is detected and named. Whoever holds the key could sign a different log, so publish the public key and pin it when you verify.
LIMIT
What does a receipt actually prove?
That this proxy observed and signed the call. It does not prove the host machine was uncompromised. There is no TEE attestation yet.
LIMIT
Is the property proof zero knowledge?
No. It is selective disclosure with a trusted attester. The verifier checks signatures, Merkle inclusion and the proxy’s attestation, but it trusts the proxy key for the policy verdict over hidden args.
LIMIT
Is the shell tool a sandbox?
No. It is a demo policy guard: shell accepts only direct pwd, ls and cat, and secret-path checks are glob heuristics. Use an isolated workspace.
SETUP REQUIRED
Are Zetaris and Meterless live?
The clients and the live-check panel exist, but no keys are configured, so the panel shows “Setup required”. Neither is used in the agent loop yet and no live call has run.
NOT RUN YET
Has the GitLab Duo flow run?
Not yet. The flow YAML, the receipts bridge and .gitlab-ci.yml are in the repo. There is no public GitLab repo, live Duo run or pipeline history yet.
SETUP REQUIRED
Is the session anchored anywhere?
Not by default. The root is not anchored on-chain. Walrus upload works only when WALRUS_PUBLISHER_URL points at a funded publisher, and none is bundled.
